## 2. Existing URLs (44 in sitemap)

1 home · 5 hubs (/calculators, /calendar, /time, /guides, /faq) · 17 tool pages · 14 guides · 7 static (about, contact, privacy-policy, cookie-policy, terms, disclaimer, report-an-error). All served as pre-rendered HTML shells generated by `scripts/generate-route-html.mjs` (44 shells) with canonical + OG + title + description per route; SPA client re-renders the same metadata (`routeSeo` in `src/App.tsx`).

## 3. Existing date-calculation functionality

Shared helpers in `src/App.tsx`:

- `today()`, `localDate()` (ISO → local midnight), `prettyDate()` (en-GB long), `weekday()` (en-US name), `shiftDays()` (calendar-day move), `dayGap()` (UTC-safe exclusive day difference), `unit()` (pluralizing count), `decompose()` (anniversary y/m/d + weeks + total months).
- `zoneOffset()/zoneToUtc()` for named-zone conversion (time-zone tool only).
- Business-day walk lives inline in `BusinessDateCalculator` (step day by day, count Mon–Fri).
- Age logic inline in `Calculator` (borrow algorithm). Week number inline (ISO Thursday rule). Leap year inline (Gregorian rule).
- No recurrence engine, no quarter logic, no month-arithmetic helper (adding months is only discussed in prose; no tool adds months), no date-format parser/formatter, no file export (CSV/ICS) anywhere.

## 4. Existing SEO pages

- 17 tool pages: auto H1 + lead (`answer`) + "How to Use" + N content sections (block renderer: p/h3/ol/ul/table/note) + Related Calculators + Related Guides + FAQs. Content lives in `src/content/*.ts` (`ToolContent` model), spread through `src/content/index.ts`.
- 14 guides (`GuidePage`, `guides.ts`), FAQ page, 7 trust/legal pages.
- Structured data: `WebApplication` JSON-LD per tool route, `Article` per guide, FAQ schema on home; all set client-side in `updateSeo()`.
- Titles: `seoTitle` per tool (≤60 chars, em dash) — must match shell `<title>` (enforced by QA script).

## 5. Existing keyword/topic coverage

Covered clusters: date arithmetic (add/subtract/between/from-today), age, working/business days, weekday/ISO week/leap year, countdown/time-since/time-difference/time-zone, work-hours, date formats *explained* (guide `/guides/date-time-formats` only — no tool), deadline *prose* (mentioned across pages — no deadline tool), year/quarter *not* covered (no quarter, no day-of-year, no days-left-in-year), recurrence not covered (only prose "recurring" mentions).

## 6. Existing internal-linking structure

- Tool pages: inline markdown links (`[Label](/path)` in content), `related: [slug…]` arrays → "Related Calculators" grid, `guideSlugs` → guides grid. Home shows all tool cards; hubs filter the same `tools` array by category; header "Find a tool" search over titles/summaries.
- Guides: `toolSlugs` back-links to tools. FAQ page: hand-written inline links.
- Every route is reachable (QA: 0 broken links, 27 unique link targets).

## 7. Missing functionality (candidates against the 20 keywords)

- Recurring/repeating date schedules (no generator anywhere).
- Deadline planning (forward deadline and reverse/latest-start) — only prose workarounds.
- Quarters (calendar or fiscal) — no quarter tool at all.
- Day-of-year / days remaining in year — no ordinal-date tool.
- Date format conversion — guide explains ambiguity but nothing converts.
- Business days in a year — no page answers it (only generic working-days counting).
- Shift schedules, payroll calendars, standalone ICS generator — no coverage.

## 8. Possible keyword cannibalization risks

- "Deadline calculator" vs existing date-calculator / business-date / subtract-days: all mention deadlines but none answers "deadline = start + duration" or "latest start = deadline − duration". A dedicated two-mode tool is a distinct job; existing pages must link to it rather than compete.
- "Days left in year" vs countdown/days-calculator: countdown targets a chosen date; days-left-in-year is year-scoped ordinal math — distinct; must state the difference.
- "Date format converter" vs the date-time-formats guide: guide = explanation, tool = conversion; link both ways, no duplicate copy.
- "Quarter calculator" vs week-number: different period unit; cross-link only.
- "Recurring date calculator" vs add-days/days-calculator: add-days moves one date; recurrence emits a series — distinct, but pages must not answer "recurring" queries with plain +30-day prose.
- "Business days in a year" on working-days page (content expansion) must not spin up a separate near-duplicate page.

## 9. Pages that should be expanded (not duplicated)

- working-days → add "business/work days in a year" section (6,900 US volume across two variants lives here).
- date-calculator → link the deadline planner for start+duration questions.
- days-calculator → link deadline + recurring where prose currently dead-ends.
- countdown / days-between → link day-of-year for year-scoped counts.
- week-number / leap-year → link quarter + day-of-year in related arrays.
- date-time-formats guide → link the new format converter.

## 10. Genuine new opportunities (summary)

Supported by Ahrefs exports + live SERPs: deadline calculator (parent `deadline calculator` 5,600/mo, KD 7), recurring date calculator (SERP = dedicated tools, no Ahrefs data — intent verified), quarter calculator (KD 0, TP 34,000), day-of-year/days-left-in-year (600/mo KD 18 + TP 6,000 cluster), date format converter (SERP = dedicated converters; ISO variant TP 3,500). Not supported: shift schedule (20/mo, TP 10), payroll calendar (20/mo, TP 150), standalone ICS page (20/mo) — ICS export instead ships as a feature of the recurring tool.

## Technical baseline

- Stack: Vite 8 + React 19 + TS 6 SPA; custom hash-free path router (`useRoute`/`NavLink`); no UI library; no external runtime deps beyond React.
- Commands: `npm run dev`, `npm run lint` (oxlint), `npx tsc -b`, `npm run build` (tsc + vite + route-shell generator). No unit/browser test framework in repo; verification = build + custom QA scripts (content bundle audit, shell/sitemap audit, calculation harness).
- Deployment: `public/.htaccess` (Apache) and `vercel.json` catch-all rewrites; robots.txt allows all except `/internal/` and `/docs/`, points at sitemap.
- Accessibility: skip link, `role="alert"` errors, `aria-live="polite"` results, labelled inputs, visible focus CSS (19 aria/role/skip references in App.tsx).
- Performance: single bundle (~456 kB / 133 kB gzip), all calculations client-side, no APIs. Privacy: inputs never leave the browser.
